wsp, in six pictures

A control plane for work and for the agents doing it. wsp owns the durable half — projects, tasks, decisions, worklists, as markdown in a git repository. herdr owns the live half — workspaces, panes, and the agents running in them. wsp joins the two and pushes the join back into herdr’s sidebar.

What you get

  • Work is plain files in git. One markdown file per project, task and worklist; every command commits what it wrote and nothing else.
  • Projects nest, and what you set on one applies below it — tags, decisions, and the handbook an arriving agent is given.
  • Every id says where its task lives, with six statuses and sub-tasks the tool keeps honest: a parent cannot be finished over an open child.
  • One command puts an agent on a task — its own worktree, its own branch, and a briefing it opens with rather than has to ask for.
  • One command ends it — agent stopped, work put down, checkout removed only if it is clean.
  • You can talk to an agent mid-run, and it can raise a hand back. A question ends by being answered or abandoned, never by being ignored.
  • A queue of work runs in order, group by group, stopping at a barrier for your verdict before the next group starts.
  • Agents run on another machine the same way they run here — with no store, no state and no wsp binary to keep in sync over there.
  • One person can hold all of it — a coordination seat per project, and a subscription that names the seven things worth being interrupted for.

Six mechanisms carry nearly all of it: how work is filed, how an agent is put on a piece of it, how you talk to that agent afterwards, who answers when it asks for something, how a queue of work is run in order, and how any of that happens on a machine nobody is sitting at. Each picture below is one of them. The vocabulary is exact — where two words look interchangeable on this page, they are not.

01Projects, sub-projects and tasks

Projects form a tree. A sub-project is a project whose parent is another project — the same kind of node, one level down — and that distinction carries weight: tags, decisions and the handbook inherit down the chain, and a task takes its id prefix from the project it lives in. Tasks hang off projects; sub-tasks hang off tasks.

  • Two node kinds, and one is nested. shop is a project; catalogue and checkout are its sub-projects. A project carries tags, decisions, a handbook and its roots — the checkouts its work lives in — and every one of those inherits down the chain, root first.
  • An id says where a task lives. <project>-NNN, continuous within a project rather than within a day. The prefix is the project’s code, which defaults to its slug, so a mistyped digit lands on an id that does not exist rather than on a real task somewhere else.
  • Six statuses, and two of them are stopped. todo → doing → review → done, plus blocked — somebody owes you an answer — and parked, which is a judgement that the moment is wrong and names the trigger that would bring it back. Both insist on a sentence.
  • Review is where an agent stops. done belongs to the person the work is for.
  • A parent cannot be finished while a child is open — the CLI refuses it and names the count; --force is the override.
  • The whole record is files. One markdown file per project, task and worklist under ~/wsp, and every command commits the files it wrote and only those.

02Putting an agent on a task

One verb does it: wsp spawn <id> --agent. The order inside the verb is the whole design — workspace, claim, agent, sentence — because the claim has to be on record before the agent’s session starts and reads it.

  • The claim is the step that can refuse. Work another live pane holds is refused and names the holder; work already done is refused because taking it would silently reopen it. Both happen before anything is written, and each refusal is a reason not to put an agent there.
  • The duplicate briefing is gone by construction. Because the claim exists first, wsp brief --session at session start describes the real task, and the work order does not have to repeat it.
  • The workspace carries where it is. It is labelled after the work and holds WSP_PROJECT and WSP_TASK in its environment, so a verb run inside it knows what it is standing in without being told.
  • A spawn does not move your screen, and it is trimmed by default. --focus asks to be taken there; --full starts the agent with the sub-agents, workflows and MCP servers it is otherwise spawned without; --model and --effort say what tier to start at, --kind picks the agent, and --on <machine> runs it on another machine.
  • Ending it is one verb. wsp despawn — the three-step hand procedure left eighteen worktrees standing after one overnight batch. --keep-tree leaves the checkout where it is. Nothing reaps on idleness: an agent idle for ten minutes may be waiting on you.
Four words for four different things
claimwhich task a workspace holds — the durable half of “who is doing this”. Claims outlive panes.
bindingwhich task a pane holds. Perishable, and rebuilt from the claims by wsp reconcile.
pinwhat a workspace is, independent of any task; --top keeps it out of the project tree entirely.
mandatestanding direction for a workspace — work in this project without being asked again. It ends on --clear or when the backlog runs dry.

03Talking to a running agent

Three channels between the work and whoever is coordinating it, and they fail in different ways, which is why there are three. A flag cannot time out but does not arrive on its own; a tell arrives but can be talked over; a question can be left open, so it is the one that refuses to close quietly. Who a raised hand reaches is the next picture.

  • A flag is state, not store. It sits beside the claims — no commit, nothing in the task file — and surfaces as a card pinned above the agents in the panel, without anybody pressing anything. Two hands on one task are two hands.
  • An ask is not a flag, and clearing is not answering. --clear acknowledges a hand; a question ends only by being answered or abandoned, both of which reach the asker. Clearing after answering down some other channel once looked like answering while the asker sat waiting. --ask claim is the one ask there is so far, and it is a closed vocabulary deliberately: the answer is a keystroke that runs a command, so an agent never names its own argv.
  • A repeat has to be meant. The same sentence to the same pane inside two minutes is read as a retry and refused — --again is how you say you meant it — because a status probe’s timeout once stood in for the verdict on a message that had already arrived.
  • A tell is the repair for a stopped turn, not a restart. The conversation is intact; a respawn throws it away.

04The seat, and what it is told

A governor is a slot on a project — a third kind of node beside projects and tasks, and affordable precisely because it is a slot: no status, no prose, nothing to finish. It adds the one edge a claim does not have. A claim is agent-to-task; a seat is agent-to-project, which is what gives a raised hand somewhere to go and lets wsp wip tell an agent sequencing work from one that has stalled. Seats nest the way projects do: a governor’s own governor is the one on the project above it, and the person is the end of the chain.

  • One agent, one governorship. Taking a second slot hands the first back. The seat has a place of its own — drawn under its project, its workspace and pane named after the position, and neither a claim nor a release writes over that name.
  • A coordination point, not an approval gate. No verb consults a seat before acting. The one guard runs the other way: wsp despawn refuses to end a governing pane without --force.
  • A governor is told a different job: sequence what runs next, write the direction an arriving agent needs, review finished work against the code rather than against the report, and hold the record — and not “go and claim something”, which is the move that turns a governor back into an agent working somebody else’s task.
  • A vacancy is not the same as no seat. wsp govern --clear stands down and leaves the slot standing for the next occupant; --remove is the separate decision that this project has no governor at all.
  • You name what you care about, not which field answers it. needs-a-person is an agent stopped with nothing said about why — one that did say why draws unanswered instead. seat-stalled exists because a seat is exempt from needs-a-person: a governor is idle between the agents it sequences, so the one agent whose failure ends a whole run would otherwise raise nothing. And blind cannot be subscribed to or switched off — it says wsp has lost sight of the fleet, which is the difference between a quiet fleet and half a world.
  • A stall has to hold before it is worth a line — five minutes by default, because an agent is “stopped” for a few seconds between every pair of turns. A modal holding the keyboard is said at once.
  • A wake is expensive, so it has to be earned. Every line that reaches a governor re-invokes it and its whole conversation is re-read — 208K tokens on one measured seat, the same for a heartbeat as for a real question. So the daemon judges what is worth a context read, holds the rest, and drops none of it; a held fact older than --defer-max becomes a wake by itself, so a quiet fleet still delivers its backlog.
  • Delivery asks where the keystrokes land. A wake is typed at a pane, and three states are not deliveries: a pane stopped on a permission dialog takes the text into the dialog, an agent still starting refuses it, and a pane that cannot be asked may hold no agent at all. It is held in all three, because the queue lives inside the agent and a wake handed to one that is then cleared or killed has been recorded as delivered and never read.
  • Nothing about it is opt-in, and the seat is the off switch. wsp govern --clear vacates the slot, the wake answers the seat is empty, and the spool holds everything until somebody sits down again.

05Worklists

A worklist is an ordered queue of groups of task references, run group by group with a barrier between them. It references its members across projects and owns none of them. Running one is three words on repeat, and each answer names the command that comes after it.

  • A plan is references. Members keep their ids and their projects — a list orders work from anywhere in the tree and owns none of it.
  • A group’s members start together. xN caps the work; a machine caps the fleet; the smaller of the two wins, so a group may ask for fewer than it is allowed and never for more.
  • The barrier is the verdict point. A barrier with prose at it will not pass until wsp worklist go is given a sentence, and that sentence is dated onto the group. Uncommitted work stops any sweep.
  • Nothing spawns by itself. next answers for the caller and names the command; a governor runs it. That is the difference between a queue and an autopilot.
  • Editing is write-ahead-only, and needs no field to say so: the line is wherever the run has reached, and it moves on its own.

06Agents on another machine

A second machine, driven from the one you are sitting at. The far machine is an executor and never a seat: nobody sits at it, and it holds no store, no state and no wsp binary — which is why there is no sync of ~/wsp, no merge story for two repositories that both autocommit, and nothing over there to hot-patch when you ship a fix. The lower half of this picture is intent rather than shipped mechanism, and is marked as such.

  • The seat is the one source of truth. wsp on the executor is a shim that runs the seat’s binary back over the same connection, so the traffic goes both ways: the seat ssh’s out to hold the tunnel, and every verb an agent runs over there ssh’s back. A one-directional reading of that is the first thing that fails.
  • The id is the routing key. herdr has no idea another herdr exists — its socket API is 89 methods and not one of them has a host in it. A remote pane is w0:p3@mb2; the @machine picks the socket and is stripped on the way out. Calls that carry no id fan out across every reachable machine.
  • Unreachable is not empty, and that is worth being paranoid about. A machine that is down reports no workspaces, which looks exactly like a machine with nothing running. So a machine must have been heard from before anything it holds is released — otherwise one dropped link hands back every task the executor is holding while its agents carry on working.
  • The cap is on the machine, not on whoever asked. Two plans each holding a number neither can honour is what that fixes. A worklist group’s xN caps the work; the smaller of the two wins.
  • Where it is going. The recorded direction is that remote is a decorator over any backend rather than a property of herdr, and that the port is written in wsp’s terms — “place work”, not “create a workspace and split a pane”. A headless herdr server is the likely substrate on the far machine either way; what changes is that it stops being the only thing that could be there.
  • What is deliberately not decided. How code reaches the executor and how the work comes back — push git to git, or work in a worktree over there. Until that settles, an agent on an executor is a shell in a home directory that can reach the store. There is no affinity either: placement is asked for with --on, never inferred, because auto-placement hides the thing you most want to see.
