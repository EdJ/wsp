# wsp-303 — does the `ask` row in the brief change how an agent asks?

The brief gained two lines (`cmd_brief::asking`): when the person has to decide, run
`wsp ask <id> --person --wait --choices -` with a `{kind: ask, questions: […]}` on stdin, rather than the
agent's own question tool or a question in the reply; `AskUserQuestion` still works. Measured on 2026-10-20.

## Method

One throwaway agent per run, in an empty directory, with a stub `wsp` on PATH that logs argv and stdin and
answers an `ask` at once (no real question reaches the store). The task needs the person: "Ed has a preference
between `--oneline` and `--compact`, written nowhere; create flag.txt with the name he wants." **With** = a
hand-built brief in `wsp brief --session`'s format carrying the two `ask` rows; **without** = the same brief
minus them. Two work orders: **order** = the real `Handover::Spawned` sentence, which already says "Something you
need decided? `wsp ask <id> "..."`"; **bare** = that sentence without the ask clause. Three runs per cell.

- Claude: Sonnet 5.5, Claude Code 2.1.304, `--safe-mode` (no CLAUDE.md, hooks, memory), interactive in a pty
  (driven with `expect`; `AskUserQuestion` is not offered in `-p` mode, so `-p` could not test the competing tool).
  The brief went in with `--append-system-prompt`, not the SessionStart hook.
- opencode: `opencode/mimo-v2.6-flash-free` (nemotron-3-ultra-free returned a 503), brief via the `instructions`
  file as wsp spawns it, `opencode run`, bare order only.
- A run "asked the person" if the stub saw `ask … --person --wait`. "Asked a seat" = `wsp ask` without it
  (goes to the coordinator, answered later, typed back at the composer).

## Results

| agent | work order | brief | `--person --wait` | plain `wsp ask` (a seat) | `AskUserQuestion` | no ask |
|---|---|---|---|---|---|---|
| Claude, interactive | order | with | 3/3 | 0 | 0 | 0 |
| Claude, interactive | order | without | 0/3 | 3 | 0 | 0 |
| Claude, interactive | bare | with | 3/3 | 0 | 0 | 0 |
| Claude, interactive | bare | without | 0/3 | 3 | 0 | 0 |
| Claude, `-p` | order | with / without | 3/3 / 0/3 | 0 / 3 | n/a | 0 |
| Claude, `-p` | bare | with / without | 3/3 / 0/3 | 0 / 3 | n/a | 0 |
| opencode (mimo free) | bare | with | 2/3 | 0 | n/a | 1 |
| opencode (mimo free) | bare | without | 0/3 | 1 | n/a | 2 |

(Claude `-p` runs: 12 more, same split.) Every Claude run asked and then wrote flag.txt from the answer.

## What this says, and does not

- Without the lines Claude already asks through wsp — the brief's `seat` row says `wsp ask <id>` — but the ask
  goes to the coordinating seat, not the person, and is not waited on. The lines change **where** the question goes:
  0/12 → 12/12 on `--person --wait` for Claude (twelve runs per arm: six interactive, six `-p`).
- **`AskUserQuestion` was 0 in all runs, with and without the lines.** In this task and with a `seat` row in the
  brief Claude never reached for it, so the preference over `AskUserQuestion` is not shown by these numbers,
  only that nothing competed with the new path. A task framed as a choice among options in a brief with no `seat`
  row (a bare `claude` session) is the case still unmeasured.
- opencode's free model is weak: n=3, one with-run explored `wsp --help` and stopped without asking, two
  without-runs asked nothing. 2/3 vs 0/3 on the person is a direction, not a rate.
- The brief was hand-built to the real format, not produced by the new binary; the SessionStart hook path
  (additionalContext rather than system prompt) is untested here.
- Fixture: stub answers instantly, so the blocking wait itself was not exercised.
